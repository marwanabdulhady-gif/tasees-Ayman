# Extraction pipeline (reproducible, offline at runtime)

The build tools require Python 3.10+ and Node 20+ **at build time only**. The
finished application has no runtime dependency on either.

```bash
# 1. toolchains
python3 -m venv .venv && .venv/bin/pip install pymupdf pillow
(cd tools/ocr && npm install)
bash tools/ocr/fetch_langdata.sh          # Arabic + English LSTM models (GitHub API)

# 2. forensics -> data/source_documents.json, data/page_inventory.json,
#                docs/CORPUS-AUDIT.md
.venv/bin/python tools/audit_pdf.py

# 3. page images + thumbnails -> assets/pages, assets/thumbnails,
#                                data/asset_manifest.json
.venv/bin/python tools/extract_assets.py

# 4. OCR inputs -> .cache/ocr/images, data/ocr_jobs.json
.venv/bin/python tools/prepare_ocr_images.py

# 5. Arabic OCR -> assets/ocr/<docId>/pNNN.json  (resumable, 4 workers)
node tools/ocr/run_ocr.js 4

# 6. content manifest + search index  (added with the application build)
```

Source PDFs are **not** committed. Place the three files in `google_drive/`
under the names listed in `data/source_documents.json`; the audit script verifies
their SHA-256 hashes. Their original Drive ids are recorded there as well.

## Provenance rules

1. `data/page_inventory.json` is the per-page source of truth for structure.
2. `data/asset_manifest.json` maps each page to its raster assets and pixel size.
3. `assets/ocr/...` holds raw OCR text **and** word boxes. Text is never edited
   after extraction; confidence flags are additive.
4. Verified titles live in `data/verified_titles.json` with a `source` field
   naming the exact PDF page they were transcribed from.
5. The application manifest is generated by joining 1–4; every displayed fact
   keeps `documentId` + `sourcePage`.
